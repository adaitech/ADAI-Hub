# Agenda Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publicar `/agenda` como uma página Strapi que lista todos os eventos futuros da inChurch em cards com arte, data, descrição e badge opcional da unidade.

**Architecture:** A página `agenda` é uma página comum da dynamic zone: o Hero existente e a nova seção `sections.agenda-eventos` são buscados pelo fluxo genérico `[slug]`. A seção é um Server Component que combina unidades editoriais do Strapi com eventos normalizados/cacheados da inChurch e entrega um view model a um card puramente visual. As regras de seleção e formatação continuam puras e testáveis, sem alterar o comportamento da Home.

**Tech Stack:** Next.js 16, React 19, TypeScript, CSS Modules, Jest/Testing Library, Strapi 5, inChurch Public API e Yarn 1.

**Spec:** `docs/superpowers/specs/2026-10-17-agenda-design.md`

## Global Constraints

- Trabalhar na branch atual `codex/agenda`; preservar as alterações locais já presentes e não fazer `git reset`, `checkout` destrutivo, `git add .`, commit, push ou PR sem novo pedido explícito.
- O Hero é o componente `sections.hero` já existente e todos os seus campos continuam editoriais no Strapi; o Next não ganha variante, conteúdo ou rota especial para ele.
- Eventos vêm exclusivamente da inChurch: aplicar as regras centralizadas de ativo, habilitado, “Mostrar no site”, exclusão de GC, deduplicação, recorrência e stale-if-error.
- Todos os eventos futuros gerais e de todas as unidades entram na Agenda, em ordem cronológica, sem limite e sem priorização de `destaque`.
- Badge apenas para `EventoSite.igrejaId` que corresponda a `unidade.igreja_inchurch_id`; mostrar somente `unidade.nome`. Evento geral, ID desconhecido e online sem confirmação não recebem rótulo especial.
- Cards não têm link, botão, inscrição ou evento `selecionar_evento` nesta entrega. A medição é coberta por `ver_secao` e isso deve constar no documento do componente.
- Mobile-first, CSS Modules e somente tokens existentes. Se o Figma exigir token inexistente, registrar `[VALOR NÃO ENCONTRADO]` e pedir decisão, sem inventar cor, espaçamento ou raio.
- Cada mudança de código começa por teste que falha; todo componente/rota/lib novo entra em testes unitários, integração, vitrine e nos gates automáticos exigidos pelo repositório.
- Conteúdo local criado/alterado no Strapi deve entrar no snapshot `strapi/data/adai-conteudo.tar.gz`; nenhum conteúdo de produção será alterado.

## Review Focus

- **Evento sem arte:** ele permanece no card, com fallback de data (dia e mês da primeira ocorrência futura), e não com imagem falsa ou card omitido — cobrir no teste de normalização e de renderização da Agenda.
- **Unidade não mapeada:** um `igrejaId` que não aparece no Strapi não vaza ID nem cria badge — cobrir no teste de normalização da Agenda.
- **Ordem contra destaque:** um evento marcado como destaque, mas posterior, não supera o evento mais próximo — cobrir em `eventosDaAgenda`.
- **Falha versus lista vazia:** `null` da inChurch oculta a seção; resposta válida sem futuros mantém título e mostra a cópia editorial — cobrir no teste do Server Component.
- **Hero da Agenda:** o JSON de uma página `agenda` contendo `sections.hero` é renderizado pelo `SectionRenderer` normal, mantém um só `h1` e não exige código especial — cobrir na integração de páginas.
